## 2 三批交付与核心路径

- D1 导入能继续：导入→解析→完整原文阅读→建立证据→核对→知识草稿。出口：首次使用者不用猜按钮条件、不用CLI救场，知道缺什么、下一步是什么。
- D2 检索能使用：必要核对→加入知识库→建立/启用索引→关键词检索/云端语义检索→原文定位。出口：本轮新增资料真实进入检索范围；不同检索能力及故障明确区分。
- D3 研究能演示：选择资料→创建问题→真实研究→观点/依据/分歧→报告→引用定位→导出。出口：两个真实场景和一次重复演示通过，用户体验结论单独记录。

对客演示可从已准备知识库开始，但验收必须覆盖至少一份新增文献；不以预制报告或假模型代替真实研究。完整方剂、专家Golden Set、大规模性能和安装交付不阻塞一般文献流程修复；所选资料的必要核对、真实来源和外发授权仍需满足。

## 3 用户反馈与待验证边界

1. 禁用按钮无原因、必填缺项无说明：D1.01。
2. 句子被拆为多个段落：D1.02，先定位解析/换行/分页/切片/展示层，不预判模型太小。
3. 上下文为空、路径不可点击：D1.03，区分真实边界与获取失败，支持修订内跳转高亮。
4. 无已审核证据导致知识草稿无法创建：D1.01，解开流程引导问题，不自动冒充人工审核。
5. 密钥不可读却仅提示本地降级：D2.02，分开检索和生成能力；本地关键词不依赖大模型，但不能冒充语义检索。
6. 研究未实际体验：D3.01，先验前序可用性，再验真实研究。
7. 按钮、页面划分与布局不合理：D1.UI，方案由规划/设计承担，无需用户逐个设计。

以上为用户反馈和待复现问题，不是本轮确诊或修复结论。
